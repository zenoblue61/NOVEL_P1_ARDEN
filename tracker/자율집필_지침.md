# 자율 집필·검수 지침 (2026-10-26 자율 집필 런)

사용자 지시(2026-10-26): "스스로 재점검 하면서, 오류 발견하면 수정하면서 이어서 작성하고, 승인하고 계속 작업을 진행해."
이 런에서는 CLAUDE.md 3절 6~7번의 "사람 검토"를 별도 검수 에이전트가 대신한다. 사람이 승인한 회차와 구분하기 위해 상태는 `자동승인(10-26)`으로 적는다.
그 밖의 모든 규칙은 `CLAUDE.md`와 `setting/`이 우선한다. 이 문서는 절차만 정한다.

## 1. 집필 에이전트 프로토콜 (배치: N~M화)

1. 읽기 순서: `CLAUDE.md` → `tracker/자율집필_지침.md`(이 문서) → `python3 scripts/extract_context.py --ep N --appraise --chars <이번 배치 등장 인물> --invent <발명 번호> --souls <전생자> --world <절>` 출력 → `tracker/회차표_1부.md`(또는 해당 부 회차표)에서 N~M 행. 인물이 처음 등장하는 화가 있으면 `setting/04_인물.md` 전체.
2. 한 화씩 쓴다. 다음 화를 쓰기 전에 직전 화 파일을 다시 읽는다. 회차표는 계획이다. 원고가 더 자연스러운 길을 찾으면 그쪽으로 가되, "달라지는 것"과 "복선·약속" 열은 지킨다.
3. 분량: 본문 공백 포함 5,000~5,500자(제목 줄 제외). 반드시 `python3 scripts/count_chars.py episodes/epNNN.md`로 세고, 범위 밖이면 고친다.
4. 파일 형식: `episodes/epNNN.md`. 첫 줄 `# 제N화. 제목`, 빈 줄, 본문. 본문 외 메모·해설·태그 금지. 상태창 박스는 `03` 3.3 형식(대괄호 제목 + 짧은 줄)으로, 회차당 1~3개.
5. 문장 규칙: 3인칭 제한(레온)·과거 시제. 다른 인물의 속마음을 확정 서술하지 않는다. 짧은 문단, 대사가 바뀌면 문단을 나눈다. 대사 비율 35~45%. 줄표(U+2014, U+2015)는 쓰지 않는다. 쉼표·괄호·마침표·말줄임표로 대신한다.
6. 금지: 설정에 없는 새 이름·지명·수치·기술. 필요하면 해당 `setting/` 파일에 `[제안]`으로 먼저 추가하고 원고에 쓴다(이름 없는 농민·광부·창고 사람은 이름 없이 둔다). 숙부 세력의 구체 인원 금지. 레온의 정치 감각 급상승 금지. 상태창을 레온 외 인물에게 주지 않는다. 감정은 맨손 접촉만, 하루 한도(5회, 감정 50회마다 +1)와 초과 비용(두통 → 코피 → 실신) 준수. 감정은 진단일 뿐 수리가 아니다.
7. 매 화 쓴 뒤 기록 갱신:
   - `tracker/progress.md` 회차 기록 표에 한 행 추가(상태 `초고`). 감정 누적은 실제 원고에서 센 횟수의 누계.
   - `setting/current_state.md`: 진행 표(마지막 완료 회차·다음 회차·작중 시점·추수절까지), 감정 누적·하루 한도, 발명 단계, 복선 상태, 레온 쪽 사람, 자원(결정 잔량·자금). 과거 경위는 쓰지 않는다.
   - `setting/08_복선_장부.md`: 실제로 심은 복선만 "심음"으로 바꾸고 회차 번호와 문장 한 줄 기록. 진행·회수도 같은 방식.
   - `setting/09_전생자.md` 9.4.1: 전생자가 처음 등장한 화 기록. 서로 알아본 회차 기록.
   - 새 설정을 `[제안]`으로 추가했으면 어느 파일 어느 행인지 메모(배치 보고에 포함).
8. 배치가 끝나면 `git add -A && git commit`(메시지: `N~M화 초고: 제목들`). 커밋 메시지 끝에 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` 줄. 푸시는 하지 않는다(오케스트레이터가 한다).
9. 최종 보고(10줄 이내): 회차별 제목·글자 수, 심은 복선, 추가한 `[제안]`, 회차표와 달라진 점, 다음 배치가 알아야 할 상태 한 줄.

## 2. 검수 에이전트 프로토콜 (배치: N~M화)

집필 에이전트와 별개의 세션이다. 원고를 쓴 쪽의 설명을 믿지 말고 파일만 본다.

1. 읽기: `CLAUDE.md` → 이 문서 → `setting/03_주인공_레온.md` 3.3 → `setting/07_문체_규칙.md` → `setting/04_인물.md`(등장 인물 절, 4.4 호칭) → `setting/current_state.md` → `tracker/회차표_1부.md`(해당 행) → `tracker/progress.md`(해당 행) → 직전 배치 마지막 화 1편 → 이번 배치 원고 N~M 전부.
2. 점검 항목(각 화마다):
   - 시점: 레온 외 인물의 속마음 확정 서술, 숙부 시점, 레온이 알 수 없는 정보의 사용.
   - 감정 규칙: 맨손 접촉 없이 발동, 하루 한도 초과인데 비용 없음, 사람 감정(60화 전), 레온 자신 감정 성공, 상태창에 레벨·스탯·퀘스트, 회차당 박스 4개 이상, 같은 대상 반복, 상태창이 "고쳐 주는" 장면.
   - 설정 충돌: 이름·나이·호칭(4.4)·지명·수치·계절·날짜·결정 잔량·발명 단계·누가 무엇을 아는가(4.5)가 setting·current_state·직전 화와 어긋나는 곳. 설정에 없는 새 사실이 `[제안]` 없이 원고에 들어간 곳.
   - 서사: 직전 화 끝 장면을 설명 없이 건너뜀, 준비·선택·대가 없는 해결, 레온의 정치 감각 급상승, 조연을 무능하게 만들어 주인공을 띄움, 매 화 "나아지는 것"의 부재, 같은 정보 반복(대사 → 독백 → 서술).
   - 형식: 제목 줄 형식, 본문 외 메모, 줄표(U+2014/2015), 글자 수(count_chars.py로 재측정), 상태창 형식.
   - 기록: progress.md 행과 원고의 일치, current_state.md가 배치 마지막 화 상태를 반영하는가, 복선 장부에 "심음"으로 적힌 문장이 실제 원고에 있는가(없으면 장부를 되돌린다).
3. 수정 원칙: 발견한 오류는 **직접 고친다**. 최소 수정(문장·문단 단위). 장면·사건·결말을 바꾸지 않는다. 구조적 문제(인과 붕괴, 설정 위반이 장면 전체에 걸림)는 해당 장면만 다시 쓰되 전후 연결을 유지한다. 고친 뒤 글자 수를 다시 센다. 고칠 수 없는 중대 충돌은 `tracker/progress.md` 비고 열에 `검토 필요: ...`로 남긴다.
4. 승인: 점검을 통과한 화는 progress.md 상태를 `자동승인(10-26)`으로 바꾼다. `git add -A && git commit`(메시지: `N~M화 검수·자동승인: 수정 요지`). 푸시는 하지 않는다.
5. 최종 보고(10줄 이내): 화별 판정, 고친 항목(위치·내용), 되돌린 장부 항목, `검토 필요`로 남긴 것, 다음 배치에 넘길 주의점 한 줄.
